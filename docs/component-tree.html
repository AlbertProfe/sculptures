Shared data flow

All pages read the same context state; add and remove also persist changes.

Neon database

Neon.js client reads and writes the sculptures table.

↔ load · insert · delete
Sculptures context

SculpturesProvider stores DB rows and shares state.

  • loadSculptures() Fetches the table when the provider mounts.
  • addSculpture(sculpture) Inserts in Neon, then updates context state.
  • removeSculpture(id) Deletes in Neon, then removes it from context state.
  • useSculptures() Lets each page read state and call the shared actions.
↔ read state · call actions
Active page

Gallery, Add, Remove, and Filter pages consume the same sculptures list.

Layout, App, and the provider are shared. Only one child route page is shown in the outlet at a time.
